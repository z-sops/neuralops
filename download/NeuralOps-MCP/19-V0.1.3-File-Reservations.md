# NeuralOps MCP — V0.1.3 File Reservations

> Jab kai agents ek hi repo pe kaam karein, to sab se aam masla hai ke do agents ek hi file badal dete hain. File reservation ka matlab hai: "yeh files abhi mere paas hain." Doosra agent unhe **edit** nahi kar sakta (Claude Code hook) aur **commit** nahi kar sakta (git pre-commit hook), aur yeh rok har agent pe lagti hai.

---

## 19.1 Kaise kaam karta hai

```
Backend:  reserve_files { taskId: "task_42", patterns: ["api-gateway/src/auth/**"] }
          → reservation_0001, exclusive, 1 ghante ke liye

QA:       reserve_files { patterns: ["api-gateway/src/**/*.ts"] }
          → 409: "Already reserved: api-gateway/src/auth/** → agent.backend (exclusive, until …) [reservation_0001]"

QA (Claude Code) edits api-gateway/src/auth/session.ts
          → hook blocks: "reserved by agent.backend … Pick other files, ask them, or wait."

Codex commits api-gateway/src/auth/session.ts
          → git pre-commit blocks: "reserved by another agent: … ← agent.backend"
```

## 19.2 Rules

| Baat | Rule |
|------|------|
| Patterns | Repo-relative. `**` (kai folders), `*` (ek segment), `?`. Aakhir mein `/` ho to poora folder (`src/auth/` = `src/auth/**`). `..`, absolute paths aur `C:/…` reject hote hain |
| Exclusive (default) | Kisi bhi doosre agent ki overlapping reservation se conflict karti hai |
| Shared (`exclusive: false`) | Sirf exclusive reservations se conflict karti hai. "Main yahan kaam kar raha hoon, dhyan rakhna" ke liye |
| Overlap | Jab shak ho to conflict maana jata hai: `src/auth/**` aur `src/**/*.ts` overlap karte hain. Lekin `src/**/*.ts` aur `src/**/*.css` nahi karte |
| TTL | Default 1 ghanta, max 24 ghante. Wahi patterns dobara reserve karo to naya nahi banta, purana **renew** hota hai |
| Task | `taskId` doge to task tumhara hona chahiye. Task complete ya release hone pe reservation khud release hoti hai. Handoff accept hone pe reservation **naye owner** ke paas chali jati hai |
| Release | Holder khud, ya holder ke manager / governor (stale reservation ko **force-release**). Peer nahi kar sakta |
| Revoke | Agent revoke ho to uski saari reservations release ho jati hain |
| Expiry | Expire hui reservation kuch nahi rokti |

## 19.3 Enforcement: 3 jagah

| Jagah | Kya rokta hai | Kis pe lagu |
|-------|---------------|-------------|
| `reserve_files` act | Overlapping reservation | Sab agents |
| Claude Code PreToolUse hook | Doosre agent ki exclusive file ka Edit/Write. `NEURALOPS_REQUIRE_RESERVATION=1` pe bina reservation ke edit bhi | Claude Code |
| **git pre-commit hook** | Staged files mein doosre agent ki exclusive file | **Har woh agent ya insaan jo git se commit kare**: Codex, Gemini CLI, Claude Code, aap |

Pre-commit core tak na pahunch sake to commit warning ke saath ho jata hai (merge gate phir bhi lagta hai); `NEURALOPS_HOOK_STRICT=1` pe commit block hota hai. `git commit --no-verify` git ka apna bypass hai. Isi liye asli aakhri rok merge gate (CI) hai.

## 19.4 Setup

**Har agent ko apna worktree do** (same repo, alag folder, alag token):
```bash
git worktree add ../app-codex  -b task_42-auth
git worktree add ../app-claude -b task_43-review
```

**Har worktree mein pre-commit hook lagao:**
```bash
bun run install-git-hook -- --repo ../app-codex  --token <codex token>  --url http://127.0.0.1:3031
bun run install-git-hook -- --repo ../app-claude --token <claude token> --url http://127.0.0.1:3031
```
Token `.git` ke andar save hota hai (`neuralops-token`), commit kabhi nahi hota. Agar pehle se koi pre-commit hook ho to woh `pre-commit.local` ban kar pehle chalta hai.

**Claude Code:** `integrations/claude-code/settings.example.json` (wahi hook jo pehle tha; ab file check bhi karta hai).

## 19.5 API / Tools

| | |
|---|---|
| Acts | `reserve_files { patterns[], taskId?, ttlSeconds?, exclusive?, reason? }` · `release_files { reservationId? \| taskId? \| all? }` |
| MCP tools | `neuralops_reserve_files`, `neuralops_release_files`, `neuralops_files_check { paths[] }`, `neuralops_reservations { agentId?, taskId? }` |
| HTTP | `GET /api/reservations?agentId&taskId` · `GET /api/reservations/check?path=…&path=…` · `POST /api/reservations/check { paths[] }` |
| Context | Compacted context mein `FILES RESERVED` section; inbox mein `myReservations` |
| Dashboard | "File Reservations" panel + 2 scenarios (QA ka conflict, Backend ka release) |

Ab 25 act types aur 38 MCP tools hain.

## 19.6 Verification

- `tests/reservations.test.ts`: 21 tests, jinme glob overlap, saare rules, lifecycle (complete/release/handoff/revoke), replay, HTTP, **asli git repo mein pre-commit** (doosre ki file ka commit blocked, holder ka commit allowed) aur **Claude hook** (reserved file ka edit blocked, strict mode) shamil hain.
- Poora suite: **122 tests pass**. Backend + frontend `tsc` aur lint clean.
- Browser (asli Caddy): QA ka conflict "FAILED" aata hai aur holder ka naam batata hai; Backend release ke baad conflict button band ho jata hai; golden path 10/10.

## 19.7 Limits (honest)

- Overlap jaan boojh ke conservative hai, is liye kabhi kabhi "false conflict" aa sakta hai (jaise `src/**` aur `src/db/**`).
- Paths case-sensitive hain; Windows pe `Src/` aur `src/` alag maane jate hain.
- Reservations advisory + hooks hain. Jo agent hook ke bina aur `--no-verify` se commit kare, use sirf CI merge gate pakdega.
