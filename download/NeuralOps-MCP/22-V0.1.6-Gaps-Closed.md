# NeuralOps MCP — V0.1.6 Gaps Closed

> V0.1.5 ke baad jo "limits" likhe thay, is version mein un sab ko bhar diya gaya hai. Saath hi NeuralOps Nexus ka asli code padha gaya, aur integration ab usi ke approval system ke andar hai.

---

## 22.1 Nexus ka asli code padhne se kya pata chala

| Nexus mein pehle se hai (v0.8.0) | Kya kami thi | NeuralOps kya deta hai |
|---|---|---|
| Har persona tool ka level Auto / Ask / Off; Ask tool tab tak rukta hai jab tak topic mein koi faisla na kare | Kaun kya approve karega, is ka koi rule nahi | Har action ki policy mein naam wala approver, approver chain, veto, aur koi apni request khud approve nahi kar sakta |
| Schedule / swarm runs mein Ask wale tools seedha refuse | Unattended kaam kuch act nahi kar sakta | `grant_approval`: pehle se di gayi approval, N dafa ke liye aur time limit ke saath |
| Faisla nucleus ki DB row mein save hota hai | Tamper-evident record nahi | Signed ledger |
| Spend limits | Sab personas ek saath rokne ka tareeqa nahi | Kill switch |

License: Nexus ab "Source Available License 1.0" pe hai (AGPL nahi). NeuralOps Apache-2.0 hai, is liye is ki files Nexus repo ke andar bhi ja sakti hain.

## 22.2 Kaunsa gap kaise bhara

| Gap | Hal |
|-----|-----|
| Nexus mein guard kahan lagega, pata nahi tha | `nexus-ai.patch`: `NeuralOpsToolGate` Nexus ke `ToolApprovalGate` ko extend karta hai; pydantic-ai runner mein lagta hai; `NEURALOPS_URL` set na ho to Nexus pehle jaisa hi chalta hai. Nexus ke apne test suite mein 9 naye tests hain, aur ek live test bhi hai |
| Approval sirf ek dafa kaam aati thi | `authorize {uses, validForSeconds, reason}` aur `grant_approval` (standing approval) |
| Webhook ko Nexus ki taraf receiver chahiye tha | One-click signed links: `/approve/:id` page (GET kuch decide nahi karta; POST se approver khud decide karta hai, ledger mein `via: "link"`) |
| Webhook ek hi URL pe jata tha, aur koi delivery log nahi tha | Comma se alag kai URLs, 3 attempts (turant, +2s, +10s), `GET /api/webhooks/deliveries`, har event ki unique id |
| Nexus users ko NeuralOps mein khud register karna padta tha | Supabase JWT (JWKS / HS256) se sign-in; `externalId` se link; chaho to pehle sign-in pe `human.<name>` khud ban jata hai |
| Insaanon ke ids bhi `agent.` se shuru hote thay | Ab `human.<name>` bhi chalta hai |
| Har persona ke liye alag token | Broker identity (`access: "broker"`): Nexus worker sirf un personas ki taraf se act kar sakta hai jin ka delegate woh hai (`via: "delegated"`); persona pehli dafa istemal pe khud ban jata hai |
| Har agent token poora workspace padh sakta tha | `NEURALOPS_AGENT_READ=involved` (secure mode mein default): har identity sirf woh padh sakti hai jis ka woh hissa hai; governor aur admin sab dekh sakte hain; WebSocket ke liye admin token chahiye |
| Presets fixed thay | Apne presets: `POST /api/presets`, `DELETE /api/presets/:name`, journaled |
| Hook ke blocks ledger mein darj nahi hote thay | `report_block` act: Claude/Codex/Gemini hooks aur git pre-commit har block khud report karte hain |
| `perform` yeh nahi batata tha ke kyun allow hua | Ab result mein `via` aata hai (authority / ungoverned / approval), aur `neuralops_perform_check` dry run bhi hai |

Budget gate plan se nikal diya gaya, kyunki Nexus mein spend limits pehle se hain.

## 22.4 Verification

- `tests/gaps.test.ts` (10): multi-use, time-boxed aur standing approvals; `via`; custom presets aur un ka replay; webhook ke kai receivers, retry aur delivery log; Claude hook ka block ledger mein; JWT HS256, ES256/JWKS, expiry aur audience; auto-provision; approval link (XSS escape, GET decide nahi karta, forged sig, deny ke liye reason zaroori, single decision); read scopes (tasks, context, state, ledger, manager, admin, WebSocket).
- `tests/nexus-gate.test.ts`: Nexus ka asli gate aur NeuralOps ek live core ke khilaf (6 scenarios). Isi test ne ek asli bug pakda: jis tool ke arguments khali hon, woh reject ho jata tha. Fix kar diya.
- Nexus clone mein: `test_neuralops_gate.py` (9) aur `test_tool_approvals.py` (22) pass hain. Baaki suite ka nateeja patch ke saath aur baghair bilkul ek jaisa hai (dono mein wahi 7 failures hain jo dependencies missing hone ki wajah se hain).
- Poora NeuralOps suite: **159 pass**. tsc aur lint clean.

## 22.5 Abhi bhi baqi (honest)

- Poori Nexus deployment (web app, nucleus, relay) mein nahi chalaya; test worker level pe hua hai.
- Jab governed call approval ka intezaar kar rahi ho, Nexus topic mein "Noaman ka intezaar" jaisa card nahi dikhta. Yeh baat webhook aur link se pahunchti hai.
- LiteLLM runner cover nahi hai (Nexus ki apni approvals bhi us pe nahi lagtin).
- Single process aur JSONL journal.
