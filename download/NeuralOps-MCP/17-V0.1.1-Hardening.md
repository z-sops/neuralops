## 17.3 Authority model (naya, secure)

```
Direct grant (agent.authority)      → woh action seedha kar sakta hai
Policy (workspace.policies)         → action/scope pe approval chahiye, approver = X
Task gate (task.gates)              → is task ko complete karne ke liye yeh scope lagta hai
```

**Kaun authorize kar sakta hai:** named approver, **ya** approver ke upar reporting chain mein koi, **ya** `*/*` wildcard holder. **Requester kabhi nahi.**

**Kaun deny kar sakta hai:** upar wale sab + jinke paas us scope pe `deny` (veto) authority ho (seed mein Security).

**Policy na ho to:** approval requester ke manager (`reportsTo`) ke paas jati hai. Manager bhi na ho to act `forbidden`.

**Gates hataana:** sirf `govern` authority (seed mein Architect, aur CEO wildcard se). Gate ADD koi bhi kar sakta hai.

**Single-use:** approved approval sirf usi agent, usi action/scope, usi task ke liye, ek dafa. Use hote hi `consumedAt` set.

## 17.4 Ownership rules

| Act | Kaun | Kab |
|-----|------|-----|
| `claim` | koi bhi | task unclaimed ho; owner blocked task re-claim karke unblock karta hai; escalation target takeover kar sakta hai |
| `release` | owner | pending handoff cancel ho jata hai |
| `complete` / `block` / `status` | owner | handoff pending na ho; complete ke liye task blocked na ho |
| `handoff` | owner | target exist kare, khud ko nahi |
| `accept` / `reject_handoff` | sirf `pendingHandoffTo` | reject → pichla status wapas |
| `update` | owner, managers, governors | `gates` hataane ke liye govern |
| `escalate` | owner, managers, governors | task blocked + `escalatedTo` set |
| `answer` / `counter` | recipient ya uska role (`role:qa`) | TTL expire na hua ho |

`status` ab `eta` field set karta hai (pehle har update pe `nextSteps` mein "ETA: …" jud jata tha).

## 17.5 Event sourcing: journal, replay, hash chain

- **Journal** (`data/journal.jsonl`) = source of truth: `genesis` + `register` + har accepted act.
- Boot pe journal **replay** hota hai → bilkul wahi state (same `stateHash`). Journal divergent ho to server **boot se inkaar** karta hai; history chup chaap nahi mitti.
- Crash ke dauran adhi likhi aakhri line tolerate hoti hai.
- **Ledger hash-chained:** har event ka `hash = sha256(prevHash + event)`. Kisi purane event ko chheda to `verifyChain` bata deta hai kahan toota.
- `GET /api/integrity` → chain valid? replay se wahi state bani? (`replayMatches`)
- Ids deterministic hain (`decision_0003`, `approval_0001`, `act_000007`) taake replay exact ho.
- Tokens journal mein kabhi plain text nahi: sirf sha256.

## 17.7 Asli MCP server (stdio)

`src/mcp/stdio.ts` ek real MCP server hai (`@modelcontextprotocol/sdk`). Yeh koi state nahi rakhta: har call core ko HTTP pe forward karta hai, is liye alag processes mein chalne wale agents **ek hi workspace** share karte hain.

**Claude Code:**
```bash

  -e NEURALOPS_URL=http://localhost:3031 \
  -e NEURALOPS_TOKEN=nops_demo_backend \
  -- bun /path/to/mini-services/neuralops-mcp/src/mcp/stdio.ts
```

**Codex CLI** (`~/.codex/config.toml`):
```toml

command = "bun"
```

- Tokens **estimate** hain: formatted text ka chars/4. Har response mein `method` field yahi batata hai.
- "Full" = NeuralOps ke paas task ka poora record (records + act log). Yeh kisi agent ki asli conversation se comparison **nahi** hai.
- Fresh seed pe task_42: ~1117 → ~339 (≈70%). Poore golden path ke baad ≈81% (ledger lamba hota hai, compacted chhota rehta hai).

## 17.10 API additions

| Endpoint | Kaam |
|----------|------|
| `GET /api/health` | public health check |
| `GET /api/whoami` | caller identity |
| `GET /api/inbox` | caller ka inbox |
| `GET /api/policies` | workspace policies |
| `GET /api/integrity` | hash chain + replay check |
| `GET /api/demo/tokens` | demo mode tokens |
| `POST /api/agents` | register (secure mode mein admin) → token ek dafa |

HTTP status ab error code follow karte hain: `400 invalid`, `401 unauthenticated`, `403 forbidden`, `404 not_found`, `409 conflict`, `413 too_large` (body limit 256 KB). Har error response mein `errorCode` hota hai.

Snapshot (`/api/state`, WS `state:snapshot`) mein naye fields: `mode`, `policies`, `ledgerHead`, agents pe `approverFor`. Ledger events pe `via`, `prevHash`, `hash`. Approvals pe `consumedAt`, `consumedBy`. Tasks pe `gates`, `eta`, `escalatedTo`, `createdBy`.
