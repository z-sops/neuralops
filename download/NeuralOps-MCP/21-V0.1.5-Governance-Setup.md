# NeuralOps MCP — V0.1.5 Governance Setup

> Dost ke Nexus test se pehle wala batch. Maqsad: setup ek call mein ho jaye, jab kisi insaan ki zaroorat ho to use foran pata chale, approval ki wajah record ho, aur client ka auditor sirf dekh sake, kuch kar na sake.

---

## 21.1 Kya naya hai

| # | Cheez | Kaam |
|---|-------|------|
| 1 | **Approval reason** | `authorize { approvalId, reason? }`: approver "kyun" likh sakta hai. Yeh approval pe bhi save hota hai aur ledger mein bhi (`deny` mein reason pehle se zaroori tha) |
| 2 | **Audit identity** | `POST /api/agents { ..., "access": "audit" }` se read-only token milta hai. Yeh sirf `GET /api/ledger`, `/api/integrity`, `/api/approvals`, `/api/policies`, `/api/freeze` aur `/api/whoami` padh sakta hai. Acts, tools, `/mcp` aur WebSocket sab 403. Dispatcher bhi audit identity ka act reject karta hai |
| 3 | **Policy presets** | `nexus-default`, `solo-dev`, `two-agent-team`, `production-gated`, `lockdown`. `GET /api/presets` se list, `POST /api/presets/<name>/apply {approver}` (admin) se lagao. Dobara lagane pe policy update hoti hai, duplicate nahi banti. Har policy audited admin change hai aur replay hoti hai |
| 4 | **Webhook** | `NEURALOPS_WEBHOOK_URL` pe `approval.requested`, `approval.decided`, `workspace.frozen` aur `workspace.unfrozen` events jate hain. `NEURALOPS_WEBHOOK_SECRET` do to har body `X-NeuralOps-Signature: sha256=<HMAC>` se signed hoti hai. Webhook kabhi act ko nahi rokta, fail ho to 2 second baad ek dafa retry hota hai, aur replay mein kuch dobara nahi bhejta |

## 21.2 `nexus-default` preset

Neeche wale saare actions `production` scope mein hain, aur approver wahi hai jo tum apply karte waqt do:

| Action | Matlab |
|--------|--------|
| `odoo.write`, `odoo.delete` | ERP mein likhna ya mitana |
| `db.write` | database mein likhna |
| `email.send` | email bhejna |
| `payment.send` | payment |
| `file.delete` | file mitana |
| `deploy` | deploy |

Search aur read jaise baaki actions ungoverned hain: chal jate hain, aur log hote hain. Guard mein apne tools ko in actions pe map karo, jaise `actions={"create_invoice": "odoo.write"}`.

## 21.3 Webhook ka payload

```json
{ "event": "approval.requested", "at": "…",
  "approval": { "id": "approval_0007", "action": "odoo.write", "scope": "production",
                "requestedBy": "agent.layla", "approver": "agent.noaman", "detail": "create_invoice: {…}", "status": "pending" },
  "ledger": { "seq": 41, "actId": "act_000019", "actType": "perform", "actor": "agent.layla", "summary": "…", "hash": "…" } }
```

`detail` persona ka likha hua text hai. Agar woh instruction jaisa lage to flagged aata hai.

## 21.4 Verification

- `tests/governance.test.ts` (8 tests): reason ledger mein darj hota hai; presets lagte hain, dobara lagane pe update hote hain, ghalat preset ya approver reject hota hai, aur replay match karta hai; presets API sirf admin use kar sakta hai; webhook ke requested/decided events signature ke saath aate hain aur detail flagged hota hai; freeze/unfreeze events aate hain aur receiver fail ho to retry hota hai; audit identity sirf allowed endpoints padh sakti hai aur baaki sab (acts, tools, `/mcp`, dispatcher) pe 403.
- Poora suite: **148 tests pass**. Backend + frontend `tsc` aur lint clean.

## 21.5 Limits

- Webhook sirf ek URL pe jata hai. Is ki delivery ka koi queue ya log nahi (sirf ek retry).
- Aam agent tokens abhi bhi poora workspace padh sakte hain. Sirf audit identities limited hain.
- Presets fixed hain. Apna preset banana abhi code change se hi hoga.
