## 18.3 Enforcement bahar: 3 layers

```
Agent (Claude Code)  ──► PreToolUse hook ──► NeuralOps /api/gate/status  (edit / push / deploy)
PR on GitHub         ──► neuralops-gate job ─► NeuralOps /api/gate/status  (required status check)
CI tests             ──► report-evidence ───► VERIFIED evidence (CI agent = attest)
```

### Gate status rules
- **`complete`** (merge / push to main): task `completed` ho, aur agar task us scope pe gated hai to completion pe **clearance** record hui ho.
- **Doosre actions** (jaise `deploy`): us task + action + scope ki **approved** approval ho.
- Gate pe `requireVerified` ho to VERIFIED evidence bhi chahiye.

### Claude Code hook
`integrations/claude-code/settings.example.json` ko apne app repo ki `.claude/settings.json` mein merge karein.

| Tool | Rule |
|------|------|
| Edit / Write / MultiEdit / NotebookEdit | Is agent ke paas in-progress task hona chahiye |
| `git push` → main/master | Task completed + cleared |
| `git push` → feature branch | In-progress task hona chahiye |
| `vercel --prod`, `npm publish`, `fly deploy`, `kubectl apply`, `terraform apply`, … | `deploy/<scope>` approved |
| Core unreachable | Edits warning ke saath allow (`NEURALOPS_HOOK_STRICT=1` pe block); push/deploy hamesha block |

Exit code `2` = block, aur wajah Claude ko dikhai deti hai. Hook model ke bahar, Claude Code ke andar chalta hai, is liye model use skip nahi kar sakta.

### GitHub
`integrations/github/neuralops-gate.yml` ko apne app repo ki `.github/workflows/` mein copy karein. Phir branch protection mein `neuralops-gate` ko **required** bana dein. PR ko task se link karne ke liye branch ya title ka naam `task_42-…` rakhein.

> GitHub ke runners aapki machine ka `127.0.0.1` nahi dekh sakte. Core ko secure mode + HTTPS pe reachable banayein, ya core wali machine pe self-hosted runner chalayein.

### CLIs
```bash
bun run gate-check -- --task task_42 --action complete --scope production   # exit 0 / 1 / 2
bun run report-evidence -- --type test --summary "212 passed" --ref <url>   # CI token → VERIFIED
```

## 18.4 Signed journal

- Line format: `{…record, "mac": HMAC(key, prevMac + record)}`
- `journal.head.json`: `{count, lastMac, headMac: HMAC(key, "head:count:lastMac")}`, jo truncation pakadta hai
- Key: secure mode mein `NEURALOPS_JOURNAL_KEY` (zaroori, 16+ chars). Demo mode mein `data/journal.key` khud banta hai (yeh casual edits se bachata hai, lekin us shakhs se nahi jo folder padh sakta hai).
- V0.1.1 ka unsigned journal pehli boot pe ek dafa migrate hota hai (backup ke saath) aur phir signed rehta hai.
- `/api/integrity` ab `journalFile: {signed, valid, error}` bhi batata hai.
- Tamper pe message backups folder ka path bata deta hai.

## 18.5 Admin API

| Method | Path | Kaam |
|--------|------|------|
| POST | `/api/agents` | register (`tokenTtlSeconds` optional) |
| POST | `/api/agents/:id/revoke` | saare tokens band, agent act nahi kar sakta |
| POST | `/api/agents/:id/rotate` | naya token; purane band (admin, ya agent khud apne token se) |
| PUT | `/api/agents/:id/authority` | `{authority: [{action, scope}]}` |
| POST | `/api/policies` | `{action, scope, approver}` (same action/scope pe update) |
| DELETE | `/api/policies/:id` | policy hatao |
| GET | `/api/gate/status?taskId&action&scope` | enforcement answer |

Secure mode mein admin endpoints ke liye admin token chahiye. Demo mode sirf loopback pe chalta hai, is liye wahan local user admin hai.

## 18.7 Abhi bhi baqi (honest)

- GitHub cloud runners ke liye core ko internet pe reachable banana aapka deployment step hai (HTTPS + secure mode).
- Codex / Gemini CLI ke liye hook jaisa mechanism abhi nahi hai. Unke liye CI check hi enforcement hai.
- Demo mode ki `journal.key` data folder mein hoti hai. Asli istemal mein key env se dein.
- Single process, JSONL journal (multi-instance ke liye database chahiye).
- Prompt-injection flagging heuristic hai. Yeh text ko flag karti hai, lekin har attack pakadne ki guarantee nahi deti. Asli hifazat yeh hai ke doosre agents ka text hamesha "data" ke taur pe dikhaya jaye.
